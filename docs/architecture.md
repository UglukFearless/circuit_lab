# Архитектура

## Принципы

**Единственная ответственность.** Каждая папка, каждый скрипт и каждый модуль отвечают за одну функцию: модели цепей, библиотека моделей, инструменты (сборка, сценарий, общий код), выходные файлы, документация.

**Наименьший сюрприз.** Данные хранятся и передаются в стандартных форматах предметной области, которые читают штатные инструменты: схема KiCad, SPICE-нетлист, XML-нетлист KiCad, raw-файл ngspice. Скрипты получают данные через API библиотек, работающих с этими форматами.

**Детерминированность.** ИИ-агент ищет решение задачи; найденное решение закрепляется детерминированной процедурой — моделью, скриптом, сценарием, — которая воспроизводит результат без агента. Процедура опирается на штатные механизмы инструментов и библиотек и на зафиксированные версии зависимостей. Так повторное решение задачи даёт стабильный результат и не тратит ресурсы агента.

## Структура репозитория

| Путь | Содержимое |
|---|---|
| `circuits/<цепь>/` | модели цепи: проекты KiCad (`.kicad_pro` + `.kicad_sch`), по одному на вариант; имя файла — имя варианта |
| `lib/spice/models.lib` | библиотека моделей |
| `tools/build.py` | сборка |
| `tools/simulate.py` | сценарий цепи люстры |
| `tools/circuit_tools/` | общий код скриптов, по модулю на функцию: структура репозитория, вызов внешних программ, чтение нетлиста, измерения; скрипты импортируют его из своей папки |
| `build/<цепь>/` | выходные файлы цепи |
| `docs/` | документация |
| `pyproject.toml`, `uv.lock` | Python-проект |

## Модель цепи в KiCad

Модель цепи — проект KiCad: `.kicad_sch` и одноимённый `.kicad_pro`; без `.kicad_pro` не определена переменная `${KIPRJMOD}`. Модель компонента назначается символу полями `Sim.*`; библиотека моделей подключается путём `${KIPRJMOD}/../../lib/spice/models.lib`.

Входы модели объявляются на схеме директивой `.param` со значениями по умолчанию и передаются в модели компонентов через `Sim.Params`, например `on={b1}`. Анализ на схеме не задаётся: его задаёт сценарий.

Источник сети — символ `Simulation_SPICE:VSIN`. Нейтраль помечена символом `power:GND`: в нетлисте это цепь `GND`, опорный узел ngspice.

## Конвейер

```
circuits/<цепь>/<вариант>.kicad_sch ──tools/build.py──► build/<цепь>/schematics/<вариант>.svg   изображение
                                                      ├► build/<цепь>/netlists/<вариант>.cir     SPICE-нетлист
                                                      └► build/<цепь>/netlists/<вариант>.xml     XML-нетлист KiCad
build/<цепь>/netlists/<вариант>.cir, .xml ──tools/simulate.py──► build/<цепь>/sim/
```

`tools/build.py` вызывает `kicad-cli` для каждого варианта каждой цепи в `circuits/` или только для цепей, имена которых переданы аргументами. Вариант — `.kicad_sch` с одноимённым `.kicad_pro`; автосохранения KiCad в сборку не попадают. Сообщение `kicad-cli` в stderr считается ошибкой сборки: об ошибках модели (не найдена библиотека, неизвестный параметр) `kicad-cli` сообщает только в stderr, код возврата при этом 0.

Сценарий для каждого набора значений входов редактирует SPICE-нетлист через `spicelib.SpiceEditor` (значения `.param`, директива анализа), запускает ngspice через `spicelib.SimRunner` и читает результат через `spicelib.RawRead`. Измерения вычисляются в Python по осциллограммам.

## Форматы обмена

`build/<цепь>/netlists/<вариант>.cir` — SPICE-нетлист, выгруженный KiCad: подключение библиотеки моделей, `.param` входов модели, элементы. Имена цепей — имена KiCad (`/L`, `/X_BLUE`, `GND`).

`build/<цепь>/netlists/<вариант>.xml` — нетлист KiCad в формате `kicadxml`. Сценарий берёт из него компоненты (`comp`: обозначение, символ библиотеки `libsource lib/part`) и цепи (`net`: имя, выводы компонентов `node ref/pin`). Компонент определённого типа выбирается по символу библиотеки.

`build/<цепь>/sim/raw/` — для каждого прогона сценария: колода для ngspice (`.cir`), осциллограммы (`.raw`), журналы ngspice и spicelib (`.log`, `.exe.log`).
