# Архитектура

## Принципы

**Единственная ответственность.** Каждая папка и каждый скрипт отвечают за одну функцию: модели цепей, библиотека моделей, сборка, сценарий, выходные файлы, документация.

**Наименьший сюрприз.** Данные хранятся и передаются в стандартных форматах предметной области, которые читают штатные инструменты: схема KiCad, SPICE-нетлист, XML-нетлист KiCad, raw-файл ngspice. Скрипты получают данные через API библиотек, работающих с этими форматами.

**Детерминированность.** ИИ-агент ищет решение задачи; найденное решение закрепляется детерминированной процедурой — моделью, скриптом, сценарием, — которая воспроизводит результат без агента. Процедура опирается на штатные механизмы инструментов и библиотек и на зафиксированные версии зависимостей. Так повторное решение задачи даёт стабильный результат и не тратит ресурсы агента.

## Структура репозитория

| Путь | Содержимое |
|---|---|
| `schematics/` | модели цепей: проекты KiCad (`.kicad_pro` + `.kicad_sch`), по одному на вариант |
| `sim/models.lib` | библиотека моделей |
| `sim/run_cases.py` | сценарий цепи люстры |
| `build.py` | сборка |
| `build/` | выходные файлы |
| `docs/` | документация |
| `pyproject.toml`, `uv.lock` | Python-проект |

## Модель цепи в KiCad

Модель цепи — проект KiCad: `.kicad_sch` и одноимённый `.kicad_pro`; без `.kicad_pro` не определена переменная `${KIPRJMOD}`. Модель компонента назначается символу полями `Sim.*`; библиотека моделей подключается путём `${KIPRJMOD}/../sim/models.lib`.

Входы модели объявляются на схеме директивой `.param` со значениями по умолчанию и передаются в модели компонентов через `Sim.Params`, например `on={b1}`. Анализ на схеме не задаётся: его задаёт сценарий.

Источник сети — символ `Simulation_SPICE:VSIN`. Нейтраль помечена символом `power:GND`: в нетлисте это цепь `GND`, опорный узел ngspice.

## Конвейер

```
schematics/<name>.kicad_sch ──build.py──► build/schematics/<name>.svg     изображение
                                        ├► build/netlists/<name>.cir      SPICE-нетлист
                                        └► build/netlists/<name>.xml      XML-нетлист KiCad
build/netlists/<name>.cir, .xml ──сценарий──► build/sim/
```

`build.py` вызывает `kicad-cli` для каждой схемы в `schematics/`. Сообщение `kicad-cli` в stderr считается ошибкой сборки: об ошибках модели (не найдена библиотека, неизвестный параметр) `kicad-cli` сообщает только в stderr, код возврата при этом 0.

Сценарий для каждого набора значений входов редактирует SPICE-нетлист через `spicelib.SpiceEditor` (значения `.param`, директива анализа), запускает ngspice через `spicelib.SimRunner` и читает результат через `spicelib.RawRead`. Измерения вычисляются в Python по осциллограммам.

## Форматы обмена

`build/netlists/<name>.cir` — SPICE-нетлист, выгруженный KiCad: подключение библиотеки моделей, `.param` входов модели, элементы. Имена цепей — имена KiCad (`/L`, `/X_BLUE`, `GND`).

`build/netlists/<name>.xml` — нетлист KiCad в формате `kicadxml`. Сценарий берёт из него компоненты (`comp`: обозначение, символ библиотеки `libsource lib/part`) и цепи (`net`: имя, выводы компонентов `node ref/pin`). Компонент определённого типа выбирается по символу библиотеки.

`build/sim/raw/` — для каждого прогона сценария: колода для ngspice (`.cir`), осциллограммы (`.raw`), журналы ngspice и spicelib (`.log`, `.exe.log`).
