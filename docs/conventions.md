# Правила ведения документации

## Общие

1. Документация ведётся на русском языке. Имена из кода, пути к файлам и термины без устоявшегося перевода остаются на языке оригинала.

2. Код, идентификаторы, комментарии в коде, входы и выходы программ (форматы файлов, генерируемые отчёты, вывод в консоль) — на английском языке.

3. Документация фиксирует итоговые решения и факты, а не процесс их поиска. Отвергнутые варианты не фиксируются.

4. Документация лаконична, но полна: при выборе между кратким и подробным изложением — предпочтение краткому. Пример или число уместны, когда они короче объяснения, которое заменяют.

5. Документация описывает то, что входит, а не то, что исключено — кроме случаев, когда исключение неожиданно и имеет значимую мотивацию.

6. Документ принадлежит ровно одному разделу; материал между разделами не смешивается. Перечень разделов задаёт [index.md](index.md), границы раздела-папки — его `index.md`. Корневые `README.md` и `AGENTS.md` не входят в разделы.

7. Каждый факт фиксируется один раз — без дублирования между документами. Ссылка на источник истины заменяет пересказ, а не сопровождает его: рядом со ссылкой допустимо одно предложение-якорь, без правил, чисел и условий. Исключения — документы задач в [workflow/tasks/](workflow/tasks/), которые включают сведения любых разделов, и `README.md`.

8. Один предмет описан одной моделью. Новое описание вытесняет прежнее; два описания одного предмета рядом — дефект, а не полнота.

9. Статус утверждения однозначен. Все разделы, кроме [workflow](workflow/index.md), описывают только действующее состояние проекта. Намеченные изменения существуют только в документах задач.

10. Термин имеет одно имя во всей документации. Синонимы и параллельные переводы не вводятся. Термины проекта определены в [index.md](index.md#термины).

11. Обороты «X, а не Y» или «X, не Y» — повод для отдельной проверки: под видом контраста часто прокрадывается лишнее — то, что не должно быть в тексте по правилу 5, или просто многословие. Оставлять только когда сравнение с Y необходимо для понимания X.

12. Документация не ссылается на номера строк в коде: такие ссылки устаревают быстрее текста.

13. Документ не описывает сам себя: без разделов о его назначении, порядке его обновления и его поддержке.

14. Ссылки между документами — относительные Markdown-ссылки. Имена файлов документации — строчные латинские буквы и цифры, слова через дефис. Исключения — корневые `README.md` и `AGENTS.md`: их имена заданы соглашениями GitHub и агентов.

## Стиль

15. Смягчения не используются: «стоит», «следует», «рекомендуется», «желательно», «как правило». Вместо смягчения формулируется условие: «допустимо только когда X». Если условие не формулируется — правила ещё нет.

16. Без вводных оборотов: «важно отметить», «нужно понимать», «как известно», «данный документ описывает». Текст под заголовком не пересказывает заголовок.

17. Без оценок без критерия: «мощный», «удобный», «гибкий», «эффективный».

18. Списки — для перечислений. Связи, причины и условия излагаются прозой: текст, состоящий из одних списков, читается как инвентарь и прячет логику.
