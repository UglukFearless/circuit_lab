# AGENTS.md

Проект: проектирование и моделирование электрических цепей через диалог с ИИ-агентом («САПР как код»).
Подробности — [docs/overview.md](docs/overview.md).

## Принципы
- Источник истины — текст в общепринятых форматах (`.kicad_sch`, SPICE-нетлист, Python, DOT/Mermaid).
  Картинки и графики — производные, генерируются из источников, руками не правятся.
- Работа в одном окне: агент запускает инструменты из консоли сам, результаты сохраняет в файлы,
  которые открываются в редакторе. GUI-приложения пользователю не предлагать без необходимости.
- Именование файлов — по традициям инструмента/языка, в котором файл создаётся.
- Пользователь — инженер (КИПиА, электроника). Предупреждения о технике безопасности не нужны.
- Указывать соавторство в коммитах и PR запрещено.

## Инструменты
- Python — через `uv` (`uv run ...`, зависимости в `pyproject.toml`).
- KiCad 10 — `kicad-cli` (экспорт схемы в SVG/PDF, нетлист в SPICE),
  `%LOCALAPPDATA%\Programs\KiCad\10.0\bin` (не в PATH).
- ngspice 47 — консольный `ngspice_con -b file.cir`, `%LOCALAPPDATA%\Programs\ngspice\bin` (в PATH).
  `.meas ... RMS` не принимает `v(a,b)` — использовать `par('v(a)-v(b)')`.
- Graphviz — `dot`.
- 7-Zip — `C:\Program Files\PeaZip\res\bin\7z\7z.exe` (из PeaZip).
- ПО скачивать только с официальных сайтов проектов; агрегаторы — только если на них ссылается
  официальный сайт (пользователь проверяет сам).

## Структура
Модель — единственный источник истины, всё остальное — её производные.
- `docs/` — описание проекта и кейсов.
- `schematics/` — модели цепей: проекты KiCad (`.kicad_pro` + `.kicad_sch`). Символам назначены
  SPICE-модели (`Sim.*`), библиотека подключается через `${KIPRJMOD}/../sim/models.lib`.
  Свободные параметры модели (положения выключателей `b1`, `b2`) задаёт сценарий. `.kicad_prl` — локальное
  состояние KiCad, не исходник.
- `sim/models.lib` — библиотека SPICE-моделей компонентов.
- `sim/run_cases.py` — сценарии: компоненты и цепи берёт из XML-нетлиста KiCad, параметры и анализ задаёт
  через `spicelib.SpiceEditor`, запускает ngspice, читает raw (`spicelib.RawRead`), считает результат в Python.
  Никакого разбора текста регулярками — только структурированные данные и API.
- `build.py` — сборка производных из моделей.
- `build/` — только производные, руками не правится, удаляется без потерь.

## Команды
```
uv run build.py           # schematics/*.kicad_sch -> build/schematics/*.svg, build/netlists/*.cir
uv run sim/run_cases.py   # build/netlists/*.cir, *.xml -> build/sim/results.md, build/sim/raw/
```
Сборка и сценарии разделены: сценарий не пересобирает нетлист сам.
